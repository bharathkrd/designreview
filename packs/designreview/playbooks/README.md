# Design-review playbooks

Each file here is one use case of the design-review seat. Live, blocked and planned use cases are all here.

- **Head (TOML between `+++` lines):** the id, the status, the plan, example questions, the seat tools, the tasks that test it, the triggers and whether it writes. Code reads this part.
- **Body:** when it runs, what it reads, what it checks, how the answer reads, and its limits. People read this part.
- **Numbers:** [`constants.toml`](constants.toml) lists each number a rule uses. Each entry names where the code reads it, the source, and the date a person checked it.

The playbooks do not drive the agent. The plans in [`../plans/`](../plans/) and the routes in [`../routes.toml`](../routes.toml) do that. A playbook is a claim about them, and a script proves the claim:

```
python scripts/playbooks_check.py           # check the playbooks, the index and the constants
python scripts/playbooks_check.py --write   # also rewrite the index below
```

The check fails in these cases:

- a live or blocked playbook names a plan that does not exist;
- an example question routes to another plan;
- a playbook uses a tool that a seat does not offer;
- a blocked playbook lists a "missing" tool that a seat offers;
- a task or a plan belongs to no playbook;
- a number in `constants.toml` differs from the code.

**Status:**

- **live:** built and tested by tasks.
- **blocked:** the agent refuses, and `blocked_by` says why.
- **spec only:** designed and not built. Every seat offers each tool it needs, and today the agent declines its questions.
